# ZedBoard On-Board OLED Display via a Custom AXI4-Lite IP Core

A bare-metal embedded project running on the **ZedBoard (Zynq-7000 SoC)** that drives the board's **built-in OLED display** (SSD1306, 128x32) using a fully self-designed AXI4-Lite IP core (`myoledctrl`) in the Programmable Logic (PL), instead of a vendor-supplied one.

![Block Diagram](block%20diagram.png)

---

## What Does This Project Do?

- Powers up and initializes the on-board SSD1306 OLED entirely through the custom `myoledctrl` peripheral
- Shows a boot message on the OLED itself (`SYSTEM ONLINE!` / `READY FOR INPUT.`) as soon as initialization finishes
- Presents a 4-option menu over the UART serial terminal:
  1. Clear screen (black)
  2. Fill screen (solid white)
  3. Fill screen (checkerboard test pattern)
  4. Type text onto the screen live, character by character, with echo back to the terminal and automatic line wrapping
- Renders text using a hand-embedded 5x8 bitmap ASCII font, with a fallback "box" glyph for any non-printable character

This goes a step further than the plain type-and-display demo used in the sibling projects — it adds an on-screen boot message and test-pattern fills alongside the live typing mode, but the underlying hardware story (PL-offloaded SPI via a custom IP) is the point of this project.

---

## Why a Custom IP Core Instead of the Vendor PmodOLED IP?

The sibling project [`zenboarrd_oled_throughipblock`](../zenboarrd_oled_throughipblock) drives an **external Digilent PmodOLED** module through Digilent's own AXI SPI/GPIO IP core, pulled in from the `vivado-library-master` vendor library. This project targets the ZedBoard's **on-board** OLED instead (no Pmod cable, no external module — it's already wired into Bank 13 of the FPGA) and drives it with an AXI4-Lite peripheral written from scratch.

Building the IP by hand means:

- Every register, every bit, and every SPI clock edge is understood and controlled directly, rather than depending on a vendor's driver stack
- The core only implements exactly what this project needs — a control register and an 8-bit shift-out engine — instead of a general-purpose SPI/GPIO peripheral with unused features
- It's a complete round trip through Vivado's IP Packager: writing the RTL, wrapping it as a catalog IP with `component.xml`, and instantiating it in a block design like any other IP
- It demonstrates that the PL-offload benefits below don't require a vendor IP — a minimal hand-written core gets the same benefits

| Feature | PS Software Only (`zenboard_oled`) | Vendor PL IP (`zenboarrd_oled_throughipblock`) | Custom PL IP (this project) |
|---|---|---|---|
| SPI generated by | CPU bit-bang loop | Digilent PmodOLED IP | Hand-written `myoledctrl` IP |
| CPU load during transfer | 100% occupied | Nearly 0% | Nearly 0% |
| Timing accuracy | Software delay loops | Hardware clock-precise | Hardware clock-precise |
| Display used | On-board / Pmod OLED (bit-banged) | Digilent PmodOLED (external) | ZedBoard on-board OLED |
| IP source | — | Xilinx vendor library | Authored in this repo |
| Font/driver library | Custom hand-coded in `main.c` | Digilent PmodOLED library | Custom hand-coded in `main.c` |

## Hardware Design

### Block Design

`processing_system7_0` (Zynq PS) drives `M_AXI_GP0` into an **AXI SmartConnect** (`axi_smc`), which fans out to a single AXI4-Lite slave port on `myoledctrl_0`. `myoledctrl_0` drives six FPGA pins straight out to the on-board OLED — no other logic sits in the path. Reset for the interconnect and the IP comes from `rst_ps7_0_100M`, the standard Processor System Reset block.

| Port | Direction | Description |
|---|---|---|
| `oled_sclk_0` | out | SPI serial clock |
| `oled_sdin_0` | out | SPI serial data (MOSI) |
| `oled_dc_0` | out | Data/Command select |
| `oled_res_0` | out | Display reset |
| `oled_vbat_0` | out | VBAT (panel power) enable |
| `oled_vdd_0` | out | VDD (digital power) enable |

The custom IP is mapped into the Zynq's memory map at **`0x43C00000`**, 64 KB range, via Vivado's Address Editor.

### `myoledctrl` Register Map

| Register | Offset | Bits | Function |
|---|---|---|---|
| `CTRL` | `0x00` | `[0]` | VDD enable — **active low** (0 = ON, 1 = OFF) |
| | | `[1]` | VBAT enable — **active low** (0 = ON, 1 = OFF) |
| | | `[2]` | RES (reset) — **active high** (1 = normal operation, 0 = held in reset) |
| | | `[3]` | DC (data/command select) — 0 = command, 1 = data |
| | | `[4]` | START — a 0→1→0 pulse begins transmitting one SPI byte |
| | | `[31]` | BUSY (read-only) — high while a byte is currently shifting out |
| `DATA` | `0x04` | `[7:0]` | Byte to transmit, sent MSB-first |

### SPI Engine

The transmit path is a small state machine built directly into the AXI-Lite slave:

- `START` is edge-detected in hardware, so software has to generate an actual 0→1→0 pulse rather than just setting a bit
- A clock divider turns the 100 MHz AXI clock into a 3.125 MHz SPI clock (100 MHz ÷ 32)
- Each bit is shifted out MSB-first, matching the SSD1306's **SPI Mode 0** (CPOL = 0, CPHA = 0): data is set up on the falling edge of `SCLK` and sampled by the display on the rising edge
- `BUSY` is asserted for the full 8-bit transfer and clears automatically once the last bit has clocked out

## Software Architecture (`main.c`)

Everything — the register-level driver, the SSD1306 bring-up sequence, the font table, and the menu — lives in a single `main.c`, the same "everything in one file" style as the bit-bang sibling project, just talking to a hardware SPI engine instead of toggling GPIOs directly.

### `OLED_WriteByte(byte, is_data)` — the low-level driver primitive
Every other function funnels through this one:
1. Waits for `BUSY` to clear (any previous transfer finishes first)
2. Writes the byte into `DATA`
3. Sets or clears the `DC` bit in a locally tracked `current_ctrl_state` shadow variable depending on whether it's a command or pixel data
4. Writes `CTRL` with `START` low, then high, then low again — generating the pulse the hardware edge-detector needs
5. Waits for `BUSY` to clear again before returning

### `OLED_Initialize()` — power-sequenced bring-up
Rather than just firing the SSD1306 init command list, the power rails are sequenced deliberately:
1. VDD and VBAT both start OFF
2. VDD turned ON, 20 ms settle
3. RES released (display taken out of reset), 20 ms settle
4. The full SSD1306 init command sequence is sent (table below) — including `Display OFF` — while the panel is still unpowered on VBAT, so nothing is visibly driven yet
5. `OLED_FillScreen(0x00)` clears the entire GDDRAM
6. **Only then** is VBAT turned ON (100 ms settle)
7. `Display ON` (`0xAF`) is sent last

Steps 5–7 in that order are what prevent a flash of garbage pixels on power-up — the RAM is guaranteed clear before the panel is actually powered and switched on.

#### SSD1306 Initialization Commands Sent

| Command | Hex | Purpose |
|---|---|---|
| Display OFF | `0xAE` | Turn panel off during init |
| Clock Divide Ratio | `0xD5, 0x80` | Set display clock divide / oscillator frequency |
| Multiplex Ratio | `0xA8, 0x1F` | 32-row MUX (matches the 128x32 panel) |
| Display Offset | `0xD3, 0x00` | No vertical shift |
| Display Start Line | `0x40` | RAM start line = 0 |
| Charge Pump | `0x8D, 0x14` | Enable internal charge pump |
| Memory Addressing Mode | `0x20, 0x00` | Horizontal addressing mode |
| Segment Remap | `0xA1` | Mirror columns horizontally |
| COM Output Scan Direction | `0xC8` | Scan COM[N-1] → COM0 |
| COM Pins Configuration | `0xDA, 0x02` | Sequential COM pins, no remap |
| Contrast Control | `0x81, 0x8F` | Set brightness level |
| Pre-charge Period | `0xD9, 0xF1` | Set pre-charge timing |
| VCOMH Deselect Level | `0xDB, 0x40` | Set VCOMH voltage |
| Entire Display On | `0xA4` | Display follows GDDRAM content (not forced all-on) |
| Normal Display | `0xA6` | Non-inverted |
| *(GDDRAM cleared here via `OLED_FillScreen(0x00)`, then VBAT enabled)* | | |
| Display ON | `0xAF` | Turn panel on, after RAM is already clear |

### Font and Text Rendering
- `font_5x8[][5]` embeds a full printable-ASCII (`0x20`–`0x7E`) bitmap font directly in `main.c`, 5 bytes per glyph
- Any character outside that range falls back to a solid box glyph (the table's last entry) so nothing renders as garbage
- `OLED_PrintChar()` sends the 5 font bytes plus one blank spacer byte per character (6 px per character), auto-wrapping to the next of 4 pages once a line would exceed 128 px, and treating `\r`/`\n` as an explicit newline
- `OLED_SetCursor(page, column)` sets the column/page address windows (`0x21`, `0x22`) so the SSD1306 auto-increments through subsequent data writes

### UART Menu
`main()` prints the boot message to the OLED, then loops on a serial menu (`1`–`4`) for clear / fill-white / checkerboard / live-typing, echoing every keystroke back to the terminal. Typing mode exits back to the menu on Enter.

## How to Replicate This Project

### Step 1: Clone the Repository
```
git clone <your-repo-url>
cd zedboard_oled_custom_ip
```

### Step 2: Add the Custom IP as a Vivado Repository
1. Open Vivado 2025.2
2. Go to **Tools → Settings → IP → Repository**
3. Click **+** and add the path to:
   ```
   <cloned_folder>\myoledctrl_1_0
   ```
4. Click OK and Apply — `myoledctrl` should now appear in the IP Catalog under **User Repository**

### Step 3: Open the Vivado Project
1. Click **Open Project** and open `zedboard_oled_custom_ip.xpr`
2. The block design loads with `myoledctrl_0` already instantiated and connected

### Step 4: Generate Bitstream and Export Hardware
1. Click **Generate Bitstream**
2. **File → Export → Export Hardware** (include the bitstream), save as `myoledip_wrapper.xsa` (already included in this repo)

### Step 5: Open in Vitis Unified IDE
1. Open **Vitis Unified IDE 2025.2**
2. Set your workspace to the cloned project folder
3. You should see `platform` and `app_component` in the Explorer

### Step 6: Build the Platform FIRST
1. In the **FLOW panel**, select **platform** from the dropdown and click **Build**
2. This generates `ps7_init.tcl` and all BSP files — do not skip this

### Step 7: Build the Application
1. Switch the FLOW panel dropdown to **app_component** and click **Build**

### Step 8: Verify the Run Configuration
1. Open `app_component/_ide/launch.json`
2. Make sure **Initialization file** points to:
   ```
   ${workspaceFolder}\platform\export\platform\sw\standalone_ps7_cortexa9_0\ps7_init.tcl
   ```
3. Verify these are checked: **Run ps7_init**, **Run Ps7 Post Init**, **Reset Entire System**, **Program Device**

### Step 9: Connect Hardware and Run
1. No external wiring needed — the display is on-board
2. Connect USB to the ZedBoard UART/PROG port
3. Open **Serial Terminal** in Vitis (Window → Show View → Serial Terminal), connect at **115200 baud, 8N1**
4. Power ON the ZedBoard and click **Run** in the FLOW panel

### Step 10: Use the Menu
Once running, the OLED shows `SYSTEM ONLINE!` / `READY FOR INPUT.` and the serial terminal shows the 4-option menu. Press `1`–`3` for the test patterns, or `4` to type live text onto the screen (press **Enter** to exit typing mode back to the menu).

## A Note on IP Packaging Status

The block design currently labels the core **"my_oledctrl (Pre-Production)"**. That's just a Vivado IP Packager metadata field, not a functional issue — it can be finalized by reopening the **Package IP** wizard, going to **Review and Package**, and setting the package state to **Production** once the core is considered stable.
